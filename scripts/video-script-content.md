## 脚本正文

### Part 0：开场 Hook（0:00–0:25）

> [画面：快速切换 —— 终端里跑 Claude Code CLI -> cc-wrap 桌面 GUI 界面 -> 快速演示几个操作]

旁白：
Claude Code 很强，但每次都得开终端、敲命令、盯满屏滚动的文字。
要是它能像 VS Code 一样有个图形界面，该多好？
所以我干脆自己做了一个。

> [画面：展示 cc-wrap 标题栏 + 侧边栏 + 聊天主界面]

这不是套壳网页，不是 iframe 嵌入。这是原生 Electron 桌面应用，直接调 API，完整 Agent 循环，能读写文件、跑命令、装 MCP 工具。

> [画面：快速闪过特征墙——多模型支持、文件编辑、MCP 集成、终端面板]

关键是，它开源、免费。你只需要自己的 API Key。


### Part 1：解决了什么问题（0:25–1:00）

> [画面：分屏对比 —— 左边终端 Claude Code CLI，右边 cc-wrap GUI]

旁白：
用过 Claude Code CLI 的人应该懂那个痛点：
- 输出全是终端文字，代码高亮？没有。
- 想看一眼文件结构？切出去开编辑器。
- 跑个命令？得手动复制粘贴。
- 换模型？改环境变量。
- 加个外部工具（比如 Tavily 搜索）？得自己搭 MCP 代理，折腾半天。

cc-wrap 把所有东西塞进一个桌面窗口：
- 左边是对话列表和文件树
- 中间是聊天区，AI 的每步操作都实时展示
- 下面是集成终端，随时敲命令
- 右边还能打开文件编辑器，边聊边改

不需要在终端和编辑器之间反复横跳了。


### Part 2：核心亮点逐个看（1:00–3:30）

> [画面：每个功能配实操录屏，节奏要快，每条 15-30 秒]

**2.1 真·Agent 循环（1:00–1:25）**

> [画面：发一个复杂任务"帮我重构这个模块"，看 AI 自动 Read -> Edit -> Bash -> 完成任务]

这不是一问一答的聊天机器人。cc-wrap 内置了完整的 Agent 循环：
模型自主决定调什么工具、读哪些文件、执行什么命令。
发一个"帮我重构这个模块"，它自己读完代码、改完文件、跑完测试、告诉你结果。
真正干活，不只是聊天。

**2.2 多模型支持（1:25–1:45）**

> [画面：设置页面切换模型 —— Claude -> GPT -> DeepSeek -> 通义 -> MiniMax]

支持 Claude、GPT-4o、DeepSeek、通义千问、MiniMax……几乎所有主流模型。
每个模型可以配不同的 API Key 和 Endpoint。
而且自动处理了消息格式差异 —— OpenAI 格式的模型用 OpenAI 协议，Anthropic 格式的用 Anthropic 协议。
切换模型只需下拉选一下，不用改任何配置。

**2.3 MCP 协议集成（1:45–2:10）**

> [画面：添加 MCP 服务器 —— 贴一个 Tavily URL -> 自动连接 -> 在对话里用搜索工具]

MCP（Model Context Protocol）是 Anthropic 推的 AI 工具扩展标准。
cc-wrap 支持两种 MCP 传输模式：
- stdio：本地跑 Node.js/Python MCP 服务器
- HTTP/SSE：远程服务，贴个 URL 就能连

装个 Tavily 搜索 MCP，AI 就能实时联网查资料。
装个 MiniMax 视觉 MCP，AI 就能看图识别。
生态正在爆发，社区里已经有几十个现成 MCP 服务器可以直接用。

**2.4 集成终端面板（2:10–2:30）**

> [画面：Ctrl+` 打开终端 -> 敲命令 -> 拖拽调整大小]

按 Ctrl+` 弹出终端，基于 node-pty + xterm.js，跟 VS Code 的终端体验一致。
跑 git、装包、查日志，不需要离开窗口。
而且终端是独立进程 —— 关了面板再打开，进程还在跑。

**2.5 任务面板 / 计划管理（2:30–2:50）**

> [画面：发一个复杂需求 -> 看 AI 自动拆解任务 -> 逐个完成 -> 进度更新]

大需求 AI 会自动拆成子任务，面板里实时显示进度。
哪个任务做完了、哪个正在进行、还剩几个 —— 一目了然。
还能点一下切换任务状态，手动干预。

**2.6 记忆系统 + Skills 扩展（2:50–3:10）**

> [画面：记忆管理界面 -> Skills 列表 -> 展示一个自定义 Skill]

AI 会自动记住对话中的关键信息（技术栈、偏好、项目背景），沉淀到记忆库。
下次对话不用重复说"我们这个项目用 Vue3 + TypeScript"。
Skills 机制让你写一段提示词注册成一个 Skill，每次对话自动激活。
比如你每天都要对接某个 API，写个 Skill，AI 就始终知道怎么处理。

**2.7 文件编辑器 + 图片粘贴（3:10–3:30）**

> [画面：打开文件 -> 编辑 -> 保存 -> 预览 Markdown -> 粘贴一张图片]

内置代码编辑器，语法高亮、行号、查找替换。
支持预览 Markdown 文件。
粘贴图片自动保存到磁盘，AI 用视觉模型或 MCP 工具识别。


### Part 3：也说说缺点（3:30–4:00）

> [画面：变成 talking head 或 节奏放慢]

旁白：
客观说，这项目还有不少不足之处：

1. 需要 API Key —— 不是开箱即用的产品。你得自己有 Claude 或 GPT 的 API 额度。适合已经有 API 订阅的开发者。

2. 早期项目 —— 目前 1.1.0 版本，核心功能稳定，但边缘场景可能会遇到小 bug。不像商业产品那么 polished。

3. 技术门槛 —— 虽然比 CLI 友好多了，但还是面向开发者的工具。你需要理解什么是 API、什么是模型、MCP 是什么。

4. 模型差异 —— 不同模型的能力差别很大。Claude 的 Agent 能力最强，DeepSeek 等模型也能用但工具调用没那么稳。

5. 单机单用户 —— 没有云端同步、没有团队协作。就是本地桌面工具。


### Part 4：和竞品比怎么样（4:00–4:30）

> [画面：对比表格]

| 类型 | 对比结论 |
|------|---------|
| vs Claude Code CLI | cc-wrap = CLI 的全部能力 + GUI + 终端 + 文件编辑器 + 记忆系统。CLI 能做的它都能做，而且更多。 |
| vs Cursor | Cursor 是 AI IDE，重度绑定 VS Code 生态和特定模型。cc-wrap 是 AI 工作台，模型自由、工具自由、工作流自由。 |
| vs ChatGPT 桌面版 | ChatGPT 桌面版只能聊天。cc-wrap 能读写文件、跑命令、调工具、接 MCP。完全不是一个层级。 |
| vs Claude.ai 网页版 | 网页版有 Artifacts，但无法操作本地文件、无法跑命令、无法深度集成开发工作流。 |


### Part 5：适用人群 + 总结（4:30–5:00）

> [画面：回归主界面，打字收尾]

适合谁：
- 已经在用 Claude Code CLI 但想要更好体验的人
- 在用 Cursor/Windsurf 但想换更灵活方案的人
- 想低成本体验 AI Agent 编程的开发者
- 需要本地文件操作 + AI 辅助的工作流

不适合谁：
- 不想折腾 API Key 和配置的人
- 纯 AI 聊天用户（ChatGPT 网页版更适合你）
- 需要团队协作和云端同步的团队
